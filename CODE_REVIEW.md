## Architecture decisions

The parser/domain layer, archive transforms, file discovery, expression evaluation, and UI adapters now have more explicit boundaries and independently testable helpers. Command registration lives in `commands.ts`; activation wires resources and subscriptions. Shared asynchronous services have owned lifetimes and serialize mutations to their caches or archive destinations.

The existing model still integrates with VS Code and the utility facade remains widely used. This review did not replace the extension architecture, migrate every legacy default export, or upgrade the entire webpack/runtime dependency stack. Those are larger migrations with different compatibility and review requirements. No runtime dependency was added.

Two compatibility changes are intentional: statistics conditions no longer accept function calls or assignments, and the minimum VS Code version is 1.36. The former closes workspace-config code execution. The latter corrects an existing incompatibility: the previous 1.25 declaration predates the runtime required by the existing lookbehind expressions and APIs. VS Code's [1.36 release notes](https://code.visualstudio.com/updates/v1_36#_nodejs-update) document its Node 10.11 runtime. The source is checked against pinned 1.36 API declarations.
